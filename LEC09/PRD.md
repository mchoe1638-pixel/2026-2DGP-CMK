# PRD — 소닉 애니메이션 뷰어

- 근거 문서: [PRE_PRD.md](PRE_PRD.md)
- 리소스: `sonic-sprite.png`
- 상태: **확정 (4판)** — 이 판을 근거로 구현한다.
- 이 문서는 구현과 검증의 기준이다. 수치를 바꿀 때는 같은 값이 나오는 절을 모두 함께 고친다.

## 1. 개요

`sonic-sprite.png`에 있는 소닉의 모든 동작(10종, 76프레임)을 원본의 4배 크기로 순서대로 재생하는
pico2d 프로그램을 만든다. 각 동작은 5회 반복한 뒤 1초 정지하고 다음 동작으로 넘어가며,
마지막 동작이 끝나면 첫 동작부터 다시 재생한다.
걷기·달리기처럼 이동이 들어가는 동작은 프레임 재생과 동시에 화면 위치도 바뀌고,
제자리 동작은 화면 가운데에서 재생한다.

### 1.1 목표

- PRE_PRD의 조건(단일 파일, 4배 재생, 5회 반복·1초 정지·전환, 전체 순환, 최소 20회 커밋)을 모두 만족한다.
- PRE_PRD에서 정하지 않은 세 가지(이동하는 동작, 프레임 좌표, 정지 중 화면)를 이 문서에서 정한다.
- 프레임 좌표, 재생 시간, 이동 결과를 수치로 적어, 실행 결과를 문서와 대조해 확인할 수 있게 한다.

### 1.2 범위 밖

- 키 입력으로 동작을 고르는 기능 (다음 수업 LEC10에서 다룬다)
- 배경 이미지, 사운드

## 3. 사용자 시나리오

1. `python sonic_animation_viewer.py`를 실행하면 1200×600 창이 열린다.
2. 화면 가운데에 4배 크기의 소닉이 나타나 1번 동작 '대기'를 제자리에서 5회 반복한다.
3. 5회째가 끝나면 마지막 프레임을 1초 동안 그대로 보여 준다.
4. 2번 동작 '걷기'는 화면 가운데에서 오른쪽으로 걸어가기 시작한다. 걷는 프레임이 재생되는 동안
   위치도 계속 바뀌고, 오른쪽 끝에 닿으면 뒤돌아 왼쪽으로 걷는다. 5회 재생이 끝나면 멈춘 자리에서 1초 정지한다.
5. 스핀 점프와 공중 회전은 앞으로 나아가면서 1회 재생마다 한 번씩 뛰어올랐다가 내려온다.
6. 회전 진입과 포즈는 다시 화면 가운데에서 제자리 재생된다. 10번 동작 '포즈' 뒤에는 '대기'부터 다시 재생한다.
7. 화면 왼쪽 위에서 현재 동작 이름, 반복 횟수, 재생/정지 상태를 확인할 수 있다.
8. ESC 키나 창 닫기 버튼을 누르면 정지 중에도 바로 종료된다.

## 5. 스프라이트 시트 분석과 프레임 데이터

### 5.1 분석 방법

- 시트는 399×525 RGBA 이미지이고 배경은 투명(alpha = 0)이다.
- 불투명 픽셀(alpha > 0)을 8방향으로 이어 덩어리를 찾았다. 시트 전체의 덩어리는 135개다.
- 다음 덩어리 59개는 동작이 아니므로 제외했다.
  - 맨 위 제목 글자 "Classic Sonic Sprites" (21개)
  - 맨 아래 제작자 표기("Sprites by: Zeper the hedgehog", "edits by balla!")와
    그 옆에 한 장씩 있는 다른 색 고슴도치 캐릭터 두 개 (38개)
- 남은 덩어리 76개는 각각 소닉 한 프레임이고, 시트의 10개 행으로 정확히 나뉜다. 행 하나를 동작 하나로 정했다.
- 덩어리의 경계 상자를 프레임 영역으로 정했다. 상자 76개는 모두 덩어리 하나만 담고, 서로 겹치지 않는다.
- 시트의 소닉은 모두 오른쪽을 보고 있다.

### 5.2 좌표계 변환

pico2d의 `clip_draw`는 이미지의 **왼쪽 아래**를 원점으로 쓴다.
분석 도구(왼쪽 위 원점)에서 얻은 상자 (x0, y0)–(x1, y1)를 다음 식으로 바꿨다.

```
left = x0    bottom = 524 - y1    width = x1 - x0 + 1    height = y1 - y0 + 1
```

## 6. 이동 규칙

### 6.1 동작 분류와 이동 값

| 순서 | 동작 | 분류 | 속도(px/초) | 5회 재생 중 이동 거리(px) | 점프 높이(px) |
|---:|------|------|---:|---:|---:|
| 1 | 대기 | 중앙 | 0 | 0 | 0 |
| 2 | 걷기 | 이동 | 150 | 750 | 0 |
| 3 | 발차기 | 이동 | 100 | 300 | 0 |
| 4 | 회전 진입 | 중앙 | 0 | 0 | 0 |
| 5 | 스핀 점프 | 이동 | 300 | 750 | 160 |
| 6 | 질주 | 이동 | 450 | 900 | 0 |
| 7 | 최고속 질주 | 이동 | 700 | 1050 | 0 |
| 8 | 공중 회전 | 이동 | 200 | 800 | 200 |
| 9 | 정면 달리기 | 이동 | 250 | 625 | 0 |
| 10 | 포즈 | 중앙 | 0 | 0 | 0 |

- 이동 거리 = 속도 × 5회 재생 시간
- 속도는 걷기 < 정면 달리기 < 스핀 점프 < 질주 < 최고속 질주 순으로 동작의 빠르기에 맞췄다.
  발차기는 차는 모습이 잘 보이도록 가장 느리게 전진한다.
- 대기(1행)는 선 자세·발 구르기·몸 숙이기로 이루어진 제자리 동작이라 회전 진입·포즈와 함께 중앙에서 재생한다.
  그래서 이동 동작은 7종이다. (실습 예시는 회전 진입과 포즈만 중앙이고 이동 동작이 8종이었지만,
  이 시트의 대기 프레임에는 걷거나 달리는 모습이 없다.)

### 6.2 시작 위치와 방향

- 모든 동작은 x = 600(화면 가로 중앙)에서 오른쪽을 보고, 발을 기준선에 둔 채 시작한다.
- 앞 동작이 멈춘 위치는 이어받지 않는다. 동작이 바뀌면 다시 가운데에서 시작한다.

### 6.3 수평 이동과 경계 반전

- 화면을 갱신할 때마다 `x += 방향 × 속도 × dt`로 위치를 바꾼다. `dt`는 직전 갱신 뒤 실제로 지난 시간이다.
  프레임 번호도 같은 경과 시간으로 따로 계산하므로, 한 프레임이 보이는 동안에도 위치는 계속 바뀐다.
- 이동 범위: `half = (그 동작에서 가장 넓은 프레임의 폭 × 4) / 2`라 할 때 `half ≤ x ≤ 1200 − half`.
  그 동작의 어떤 프레임도 화면 밖으로 나가지 않는다.
- x가 범위를 넘으면 넘은 거리만큼 반대쪽으로 되돌리고 방향을 바꾼다(반사).
- 방향이 왼쪽이면 프레임을 좌우 반전해 그린다(시트의 소닉은 오른쪽을 본다).

### 6.4 점프 궤적

- 1회 재생 시간을 `T`, 그 회차 안에서 지난 시간을 `t`라 하면 `p = t / T`,
  점프 높이 `jump = H × 4p(1 − p)` (`H`는 6.1절 점프 높이).
- p = 0과 p = 1에서 0(발이 기준선), p = 0.5에서 최고 높이 H가 된다. 5회 재생이면 5번 뛴다.
- 5회째가 끝나는 순간 점프 높이가 0이므로, 정지 화면은 기준선 위에 선다.
- 가장 높이 올라갔을 때 그림 위쪽 끝(가장 높은 프레임 기준):
  스핀 점프 150 + 160 + 27×4 = 418, 공중 회전 150 + 200 + 45×4 = 530.
  상태 표시(화면 위쪽 약 40px)와 겹치지 않는다.

### 6.5 정지 중 위치

- 1초 정지 동안 x, 방향, 프레임(그 동작의 마지막 프레임)을 바꾸지 않는다. 점프 높이는 0이다.

## 7. 화면 배치

- 그리는 크기: `draw_w = width × 4`, `draw_h = height × 4`
- 가로 위치: 중앙 동작은 x = 600, 이동 동작은 6.3절에서 계산한 x에 그림의 가로 중심을 맞춘다.
- 세로 위치(발 기준선): `GROUND_Y = 150`. 프레임을 그리는 중심 y는 `GROUND_Y + jump + draw_h / 2`이다.
  프레임 높이(26~45px)가 달라도 발(그림 아래쪽 끝)은 항상 기준선(점프 중에는 기준선 + jump)에 놓인다.
- 1판에서는 가장 높은 프레임을 세로 중앙에 두는 210을 썼지만, 점프 높이(최대 200px)를 확보하려고 150으로 내렸다.
- 상태 표시: 화면 왼쪽 위
- 정지 중: 마지막 프레임을 멈춘 자리에 그대로 그린다.
